# 全书演化推演设计文档

## 概述

全书演化推演（Full-Novel Evolution）是 AI World Engine v1.7.0 引入的核心功能，它基于 v1.6.0 的创作上下文资产库，实现了结构化的全书级剧情演化方案生成。

## 目的

用户不再需要每次手动输入大量世界背景、主角路线、风格要求、剧情阶段。只需：
1. 选择创作上下文包
2. 填写本次推演目标
3. AI 生成 12 章节结构化全书演化方案

## 输入来源

全书演化推演整合以下输入源：

| 来源 | 说明 |
|------|------|
| 世界基础信息 | 世界名称、类型、时代、基调、简介 |
| 角色设定 | 世界中的角色及其属性 |
| 势力设定 | 世界中的势力及其关系 |
| 地点设定 | 世界中的地点 |
| 世界规则 | 世界的规则和约束 |
| 正史事件 | 已有的历史事件 |
| 创作上下文包 | 来自 v1.6.0 的 ContextPackage |
| ├─ 推演记录 | 选中的 simulation_record |
| ├─ 风格方案 | 选中的 StyleProfile |
| ├─ 剧情时间点 | 选中的 PlotAnchor |
| └─ 生成配置 | strict_canon / strict_style / target_words 等 |
| 用户推演目标 | 用户本次填写的主要推演方向 |

## 输出结构（12 章节）

AI 生成的方案严格包含以下 12 个章节：

1. **一、小说定位** — 题材方向、故事基调、读者预期、核心卖点
2. **二、全书核心矛盾** — 表层/深层/世界级/主角个人矛盾
3. **三、主角成长路线** — 初始→早期→中期→后期→最终
4. **四、特殊能力影响路线** — 能力影响、风险、代价、禁止无代价升级
5. **五、世界演化路线** — 世界运行方式、主角介入变化、势力格局
6. **六、主要势力反应** — 支持者/观察者/竞争者/敌对者/隐藏威胁
7. **七、主要人物关系变化** — 盟友/导师/对手/背叛者/情感关系
8. **八、阶段结构建议** — 5 个阶段的结构建议（不做正式分卷大纲）
9. **九、关键转折事件** — 至少 8 个关键事件，含原因/参与方/影响
10. **十、结局候选** — 稳健/高压/悲壮/开放式结局及推荐
11. **十一、设定风险与禁止越界项** — 世界观风险/主角过强/配角降智等
12. **十二、后续拆分建议** — 拆几卷、下一步做什么、需确认问题

## 方案状态

方案状态复用 `simulation_records.status` 字段：

| 状态值 | 显示名称 | 含义 |
|--------|----------|------|
| `pending` | 待确认 | 方案刚生成，尚未审核 |
| `adopted` | 主线方案 | 设为优先使用的全书路线 |
| `branched` | 备选方案 | 保留作为参考但不作为默认 |
| `discarded` | 已废弃 | 不再使用 |

### 状态操作

- **设为主线方案** (`set-mainline`): 表示后续分卷大纲优先基于此方案
- **设为备选方案** (`set-candidate`): 保留作为备选路线
- **废弃方案** (`discard`): 不再考虑此方案

## 和后续分卷大纲的关系

- v1.7.0 只生成阶段结构建议，不做正式分卷大纲
- v1.8.0+ 将基于标为"主线方案"的记录，正式生成分卷大纲
- 分卷大纲将包含各卷的详细故事线和章节规划

## 禁止自动写入正史的规则

以下操作**不会**自动写入正史：
- AI 生成的演化方案内容
- 方案状态变更（设为主线/备选/废弃）
- 上下文包加载和引用

用户必须手动审核方案内容后，如果需要将具体事件纳入正史，需手动创建历史事件。

## 页面路径

| 页面 | 路径 |
|------|------|
| 全书演化推演 | `/worlds/{id}/novel/evolution` |
| 演化方案列表 | `/worlds/{id}/novel/evolutions` |
| 方案详情 | `/worlds/{id}/novel/evolutions/{rid}` |
| 上下文包直达 | `/worlds/{id}/novel/evolution?context_package_id={pid}` |

## Mock AI 支持

Mock AI 模式（没有 API Key 时）可正常生成结构化全书演化方案，包含完整的 12 章节内容。这确保了本地测试和演示的可用性。
