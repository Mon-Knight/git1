# 开发规范 — AI World Engine

## 项目当前定位

AI World Engine 已经从"世界观推演工具"进入"小说工程化创作应用"的过渡阶段。

当前已完成：
- 世界设定管理（角色/势力/地点/规则/历史事件/时间线）
- AI 推演与分支管理
- 创作上下文资产库（风格方案/剧情时间点/上下文包）
- 全书演化推演（基于上下文包的 12 章节结构化方案生成）

下一步重点：应用化结构，而不是继续堆功能。v1.7.x 为应用化补课阶段，v1.8.0 之后再做分卷大纲。

## 不可破坏规则

以下规则任何 Agent 开发必须严格遵守：

1. **旧路由不能删除**。所有已有路由必须保持可访问。
2. **旧功能不能重写**。只能新增或增强，不能替换。
3. **旧数据不能丢失**。数据库表不能删减字段，只能新增。
4. **旧测试不能删除来换取通过**。如果旧测试失败，必须修复代码，不能删除测试。
5. **AI 结果不能自动写入正史**。所有 AI 生成内容必须先保存为 simulation_record，用户手动审核。
6. **方案状态操作不能自动创建 historical_events**。set-mainline/set-candidate/discard 只修改 status 字段。
7. **跨世界数据必须隔离**。世界 A 的数据不能出现在世界 B 的页面或 API 中。
8. **EXE 打包必须持续验证**。每次版本发布必须运行 build_exe.ps1 和 verify_desktop_build.py --all。
9. **API Key / .env / 日志不得导出**。导出 JSON 不得包含任何敏感信息。
10. **每个版本只做一个主要目标**。不可在一个版本中堆叠多个大功能。

## 数据安全规则

1. **单世界导出不能包含敏感信息**：导出 JSON 不含 app_settings、API Key、.env 内容、日志。
2. **数据库恢复前必须备份**：恢复用户数据库之前自动备份当前数据库。
3. **备份 metadata 不得泄露 API Key**：metadata JSON 只记录表计数，不记录配置值。
4. **AppData 数据库路径不能随意改变**：EXE 模式数据库路径为 `%LOCALAPPDATA%/AIWorldEngine/`。
5. **EXE 模式 backups 路径不能随意改变**：`%LOCALAPPDATA%/AIWorldEngine/backups/`。

## 开发流程规则

每次 Agent 开发必须遵循以下流程：

1. 先阅读最新完成汇报（在对话历史中）
2. 再检查 README / CHANGELOG / docs 目录
3. 以用户最新完成汇报为优先，上传文件可能不是最新版
4. 若上传文件与用户最新汇报冲突，以用户最新汇报为准
5. 每次只做任务书指定范围，不顺手加功能
6. 完成后必须运行测试（pytest tests/ -v）
7. 完成后必须更新版本号（app/config.py VERSION）
8. 完成后必须更新 CHANGELOG
9. 完成后必须检查 git status
10. 完成后必须创建 tag 并推送，除非用户明确不要求

## 提交信息规范

```
feat:     新功能
fix:      修复问题
docs:     文档修改
test:     测试相关
refactor: 重构
chore:    配置或杂项
security: 安全修复
backup:   版本备份说明
```
