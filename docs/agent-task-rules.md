# Agent 任务规则 — AI World Engine

## 文档目的

本文件定义以后给 AI Agent（Copilot/其他）下达开发任务时必须遵守的规则和格式要求。

任何 Agent 在开始开发前，必须先阅读本文档。

## Agent 开发前必须确认

以下事项必须在开发前全部确认：

1. **当前版本**：从 `app/config.py` 读取 `VERSION`，或以用户最新完成汇报为准。
2. **当前分支**：`git branch` 确认在哪个分支工作。
3. **最新 tag**：`git tag -l` 确认已有 tag，避免重复创建。
4. **git status** 是否为 clean。
5. **用户最新完成汇报**：在对话历史中查找最近的完成汇报，优先采信。
6. **README / CHANGELOG 是否可能落后**：如果版本号不匹配，以用户最新汇报为准。
7. **本任务范围**：从用户任务书中提取目标版本、本次目标、本次不做。

## Agent 不能做的事

1. **不能顺手加未来功能**。任务书说做 A，就不能把 B、C 顺手实现了。
2. **不能删除旧路由**。已存在的 URL 必须保持可访问。
3. **不能为了测试通过删除测试**。旧测试失败必须修复代码，不能删除测试。
4. **不能让 AI 自动写入正史**。AI 生成的所有内容必须先保存为 simulation_record。
5. **不能跨世界读取数据**。世界 A 的数据不能出现在世界 B。
6. **不能把小说工程和世界资料库混成一个页面**。
7. **不能把临时占位当正式功能**。未完成的功能必须标注版本号，不能伪装成已完成。
8. **不能绕过导出/导入/备份兼容**。每次新增数据必须同步更新导出导入服务。
9. **不能忽略 EXE 打包验证**。必须运行 `verify_desktop_build.py --all`。
10. **不能跳过版本号更新**。必须在 `app/config.py` 中更新 `VERSION`。
11. **不能跳过 CHANGELOG 更新**。
12. **不能跳过 Git tag**。

## 每次任务书必须包含

用户向 Agent 下达的任务书应包含以下章节：

```
任务名称：vX.Y.Z 简短标题

一、项目背景（当前版本、分支、已完成功能）
二、本版本目标
三、本版本不做
四、数据模型变更（如有）
五、服务层要求（如有）
六、路由要求（如有）
七、页面要求（如有）
八、导出/导入/备份兼容要求
九、EXE 打包要求
十、测试要求
十一、运行命令
十二、手动验收流程
十三、版本和文档更新
十四、Git 要求
十五、完成汇报格式
```

## Agent 完成汇报必须包含

每次任务完成后，Agent 必须输出以下格式的汇报：

```
一、分支与版本（分支、版本、tag、是否推送）
二、核心功能（逐项确认完成状态）
三、修改文件（新增/修改文件列表）
四、测试结果（compileall/pytest/encoding/verify/build）
五、EXE 验证（是否构建、启动是否正常、关键页面是否可用）
六、Git 状态（status、commit、tag、推送状态）
七、注意事项（本版本不做、已知限制）
八、下一步建议（下个版本做什么）
```

## 开发流程约束

Agent 每次开发必须严格执行：

1. **阅读** → 先读项目结构、最新汇报、已有代码
2. **分析** → 不假设成功，用工具验证
3. **实现** → 每次只做一个模块
4. **测试** → 每个模块完成后运行测试
5. **提交** → 测试通过后才能 Git commit
6. **标记** → 每个稳定版本打 tag 并推送

## 失败处理

如果某一步失败：
1. 停止继续扩展新功能
2. 读取并总结错误
3. 判断是环境问题、依赖问题、代码问题还是权限问题
4. 优先做最小修改
5. 修改后重新运行测试
6. 如果连续两次失败，回退到上一个稳定 Git commit，并记录原因
7. 不要删除整个项目重来
