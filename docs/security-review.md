# Security Review — AI World Engine

## 审查日期
2026-05-09（第一阶段 — 设计阶段预审）

## 安全设计原则

### 1. 密钥管理
- [x] 所有敏感配置使用 `.env` 文件
- [x] 提供 `.env.example` 模板
- [x] `.gitignore` 已排除 `.env`
- [ ] 编码阶段需确认：代码中无硬编码密钥

### 2. 输入校验
- [ ] 所有用户输入需要校验（待编码阶段实现）
- [ ] 防止 SQL 注入（使用 SQLAlchemy ORM）
- [ ] 防止 XSS（Jinja2 默认转义）
- [ ] 防止路径穿越

### 3. 数据库安全
- [x] 使用 SQLAlchemy ORM，避免 SQL 字符串拼接
- [ ] 数据库文件放在 `data/` 目录，不对外暴露

### 4. AI 调用安全
- [x] AI_API_KEY 通过环境变量读取
- [ ] AI 请求日志不记录 API Key
- [ ] AI 返回内容渲染时防 XSS

### 5. 文件上传
- 第一版无文件上传功能，暂不评估

### 6. 依赖安全
- [ ] 编码阶段需固定依赖版本
- [ ] 定期检查依赖漏洞

### 7. 错误处理
- [ ] 生产环境不暴露详细错误信息
- [ ] 自定义错误页面

### 8. CSRF 保护
- 第一版为单用户本地应用
- 后续多用户版本需要添加 CSRF 保护

## 待编码阶段确认的安全项
1. 确认 `.env` 未被提交到 Git
2. 确认所有路由有输入校验
3. 确认 SQL 查询使用参数化
4. 确认模板渲染不产生 XSS
5. 确认错误页面不泄露敏感信息
6. 确认日志不输出敏感数据
